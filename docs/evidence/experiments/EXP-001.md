# Project.rfx authoring experiment evidence

## Delivered vertical slice

- A strict versioned `Project.rfx` grammar compiles in portable C++20 into the
  existing immutable Core `ProjectSnapshot`. Qt does not parse project meaning.
- Authored time uses integer composition frames and a positive rational rate.
  Core performs checked conversion to the canonical nanosecond domain; the CLI
  reports exact start, exclusive end and duration in both frames and ns.
- The canonical serializer round-trips supported Shape, Text, Transform2D and
  scalar transform animation without introducing a second evaluator or render
  graph.
- `ReplaceProjectCommand` admits only the same project ID, expected active
  revision and exactly `active + 1`; invalid, stale and duplicate-ID candidates
  retain Last-Known-Good.
- Studio opens the real example `Project.rfx`, observes whole-file candidates,
  submits them through Application/Core authority, and activates accepted layer
  state in the Skia snapshot, Timeline model and Canvas metadata.
- Runtime creates project-local `.refusion/Journal`, `Diagnostics`, `Cache` and
  a session lock. Diagnostics are JSONL with code, message, active/candidate
  revision and source line/column. Accepted journals are immutable RFX source.
- UI rename commands serialize the same accepted project source back to
  `Project.rfx`; files and UI remain clients of one authority.
- The example project contains a project-local `AGENTS.md` and generated
  `$refusion-project-authoring` Skill with explicit units, exact workflow,
  supported-capability boundary and repair guidance.

## Verification

- `cmake --workflow --preset macos-core`: 8/8 tests passed.
- `cmake --workflow --preset macos-core-sanitized`: 8/8 tests passed under
  ASan and UBSan.
- `cmake --workflow --preset macos-visual`: 20/20 tests passed on the physical
  macOS Metal/Skia lane.
- `refusion.project_rfx`: positive compile, semantic evaluation, canonical
  round-trip, source-location syntax failure, duplicate-ID rejection and
  unsupported-property rejection passed.
- `refusion.project_authority`: complete candidate acceptance, replay, stale
  rejection, invalid semantic rejection and Last-Known-Good retention passed.
- `refusion.project_live_reload`: a filesystem Revision 2 was accepted into
  Core and Runtime, while malformed Revision 3 was rejected and created no
  accepted journal.
- Manual visual run on a temporary real project accepted Revision 2 and wrote
  `accepted-r2.rfx`; malformed Revision 3 (`pixels` instead of `px`) produced
  `RFX-RFX-PARSE-001` at line 77, column 17 while active Revision 2 remained.
- `refusion-cli validate` returned `VALID` for the 1080x1920, 30 fps, 900-frame
  example; `describe` reported all seven layers and exact ranges/transforms.
- Docs Doctor: zero problems. Architecture Check: 47 owned source files, zero
  problems.
- The official Skill validator could not start because its host Python lacks
  `PyYAML`; equivalent frontmatter checks using the same permitted fields,
  naming rule and length limits passed without installing a dependency.

## Cross-platform state

The RFX compiler, serializer, semantic model, revision authority and CLI are
standard portable C++20. Qt is confined to filesystem/watch/UI adaptation.
The current physical visual proof is macOS only. Windows, iOS and Android are
`not-run`; this evidence makes no qualification claim for them.

## Claim boundary and decision pending

EXP-001 currently authors Shape, Text, Transform2D and six scalar animation
properties. It does not author Video, Audio, masks, FX, plugins, import, save
history, migrations or export. The typed RFX format remains an experiment until
the owner tests real agent authoring and G2 compares accuracy, context cost,
round-trip behavior and failure repair against the alternatives in RFC-0001.
