# Shared GPU observability evidence

## Delivered proof

- Portable C++20 Runtime now exposes one typed observability record for device
  generation, resource/fence leases, attributed submissions/copies/conversions,
  residency, latency, thermal samples, stale rejection and device loss.
- The service is measurement-only. It cannot create a device/queue, schedule a
  frame, advance project time, mutate project state or present a drawable.
- Adapter/generation identity must match before VideoToolbox, Skia or Metal can
  attach to the record. Device loss advances the admitted generation once;
  subsequent stale renderer use is rejected and traced.
- VideoToolbox surfaces report their two actual plane-stride extents without
  mapping pixels. Skia owns a typed context lease and attributes each GPU flush.
  Metal reports drawable allocation size, presentation submission, real command
  buffer completion latency and the native process thermal state.

## Physical joint proof

The macOS integration test creates one observer and passes it through the actual
hardware decoder, dependency-aware scheduler, Skia YUVA compositor and native
CAMetalLayer presenter. Eleven B-frame/VFR dependency samples become a bounded
two-surface queue; frames 99 and 100 select source frames 9 and 10, render with
Skia, and present through Metal. An injected device loss then advances the
generation and the same presenter rejects its stale renderer.

On `MAC-LAB-001` / Apple M1, the named tier
`MACOS-METAL-INTERACTIVE-640X360/Apple M1` recorded:

- 15/15 resource leases released and 3/3 real fences completed;
- 15 attributed submissions: 11 media, 2 Skia and 2 presentation;
- zero attributed or unattributed copies and conversions;
- peak observed resident extent `2,089,728` bytes;
- maximum observed fence latency `10,732,084` ns;
- three thermal samples with maximum state `nominal`;
- one device-loss event, one stale-generation rejection and zero stale
  resources accepted;
- zero software decoder selections, CPU video-pixel maps/conversions/uploads,
  GPU readbacks, cross-adapter events or abandoned fences.

The named acceptance ceiling is 64 MiB peak observed extent, 2 seconds maximum
fence latency and thermal state no worse than `serious`. These ceilings qualify
only this bounded 640x360 Apple M1 tier and are not product-wide targets.
