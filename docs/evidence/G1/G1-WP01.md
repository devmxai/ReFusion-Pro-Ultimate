# macOS presenter evidence

## Accepted entry evidence

- Runtime device: `MAC-LAB-001`, MacBookAir10,1, Apple M1 7-core GPU, 16 GB.
- Repository-local Skia/Metal same-device contexts already pass on this device.
- Cross-platform policy is machine-enforced: common source rejects platform
  preprocessor conditionals and CMake must retain macOS/Windows Core, Studio and
  Graphics lanes.
- Windows runtime state is `not-run` because no physical device is available.

## Delivered and observed

- `ViewportRenderSession` owns frame index/time inside portable Runtime; Qt owns
  no GPU service, presenter, render clock or project-pixel path.
- The Studio composition root owns the one Metal device, Skia renderer,
  presenter and render session. QWindow sends only native host, size, exposure
  and invalidation events.
- The Apple adapter owns a CAMetalLayer and presents textures from the same
  engine Metal device/queue generation.
- Skia wraps each drawable as a Ganesh render target and shapes the Arabic/Latin
  fixture through the pinned HarfBuzz+ICU `skshaper` target.
- The application launched with the native Canvas visible and no stderr after
  the final QML anchor correction.
- The walking application now opens
  `examples/projects/reels-demo-30s/ReFusionDemoReel.refusion.json` from disk;
  a missing or invalid path returns structured `RFX-PROJECT-OPEN` and exit code
  2 without admitting a hard-coded fallback scene.
- The accepted Revision contains Composition `cmp_reels_main`, Canvas
  1080x1920, exact 30,000,000,000 ns duration, 30/1 frame rate and seven stable
  Layer IDs. Timeline, Canvas and Inspector metadata are read from that opened
  snapshot.
- Runtime, not QML/Qt, schedules the loop. Physical observation crossed the
  30-second boundary to Loop 2 while shape position/rotation and progress were
  evaluated from project keyframes.
- Portable GPU state is typed as `ready`, `suspended` or `lost`. Sleep/wake
  retains the generation only when the physical adapter survives; device loss
  increments generation and stale renderer/presenter leases are rejected.
- Metal observes native `NSWorkspaceWillSleepNotification`,
  `NSWorkspaceDidWakeNotification` and `NSWindowOcclusionState`. The D3D12 lane
  implements the same portable contract and checks device removal after wake.
- A physical full-window cover/uncover test produced occlusion suspend/resume
  `1/1` while visibility remained `0/1`, proving it was not a minimize event.
- Runtime stops at the first rejected frame and retains its diagnostic instead
  of producing an error loop or admitting a fallback generation.

## Deferred evidence

The product owner reported that the manual sleep/wake path works and explicitly
made an automated retained receipt non-blocking for continued development.
Retain that receipt when convenient. Native notification delivery, physical
occlusion/resume and injected device-loss/fail-closed behavior pass, but the
owner report must not be relabeled as automated lab evidence.

## Claim boundary

This work may establish macOS runtime behavior only. It cannot qualify Windows,
iOS, Android, all-platform support, Video Layer decode, audio, save/reopen,
export, stable project-format compatibility, G2, or G1 exit.
