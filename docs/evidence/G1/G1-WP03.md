# Apple hardware-media surface evidence

## Delivered proof

- Portable C++20 contracts describe exact signed PTS/duration, the bounded
  H.264 AVC 8-bit 4:2:0 NV12 video-range SDR Rec.709 profile, typed capability
  states, engine GPU identity/generation and strict path counters.
- Apple capability admission calls the native hardware-decode query for H.264.
- The probe borrows the engine-owned Metal device, allocates a Metal-compatible
  native NV12 surface and binds its luma/chroma planes as Metal textures.
- Both texture devices match the engine adapter ID and generation.
- A suspended GPU makes the media probe fail closed with
  `RFX-MEDIA-GPU-NOT-READY`; it performs no hidden fallback.
- The separately declared Windows media lane returns
  `RFX-MEDIA-WINDOWS-NOT-QUALIFIED` until G1-WP04 runs on real Windows hardware.

## Verification

- `macos-media`: 9/9 tests passed on MacBookAir10,1 / Apple M1 7-core GPU.
- `macos-core`: 6/6 passed.
- `macos-core-sanitized`: 6/6 passed under ASan+UBSan.
- `macos-visual`: 13/13 passed, proving no regression to the walking app.
- Architecture Check: 35 owned files, zero problems.
- Hardware admissions: 1; native surface allocations: 1; plane bindings: 2.
- Software decoder selections, CPU pixel maps/conversions/uploads, GPU
  readbacks, cross-adapter events and unattributed GPU copies: all exactly zero.
- Machine-readable receipt:
  `docs/evidence/G1/artifacts/G1-WP03-capability-verification.json`.

## Evidence still required

This slice does not decode a compressed sample. G1-WP03 remains active for a
bounded repository-owned H.264 corpus, a decompression session that requires
hardware acceleration, decoded-output PTS/color checks, engine surface

## Claim boundary

This proves macOS hardware capability and same-device native-surface interop
only. It does not qualify actual decode, audio, import, Timeline playback,
export, Windows, iOS, Android, G1 exit or product codec support.
