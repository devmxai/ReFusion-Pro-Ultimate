# Apple hardware-media surface evidence

## Delivered proof

- Portable C++20 contracts describe exact signed PTS/duration, the bounded
  H.264 AVC 8-bit 4:2:0 NV12 video-range SDR Rec.709 profile, typed capability
  states, engine GPU identity/generation and strict path counters.
- Apple capability admission calls the native hardware-decode query for H.264.
- The probe borrows the engine-owned Metal device, allocates a Metal-compatible
  native NV12 surface and binds its luma/chroma planes as Metal textures.
- Both texture devices match the engine adapter ID and generation.
- A suspended GPU makes the media probe fail closed with
  `RFX-MEDIA-GPU-NOT-READY`; it performs no hidden fallback.
- The separately declared Windows media lane returns
  `RFX-MEDIA-WINDOWS-NOT-QUALIFIED` until G1-WP04 runs on real Windows hardware.

## Actual compressed-decode slice

Source commit `1433a576e75f47fa4377259da9c095eab20291a9` adds a
repository-owned synthetic H.264 High/Rec.709 Annex-B fixture and passes one
compressed access unit through a VideoToolbox session that both requires and
reports hardware acceleration. Output frame PTS `3/30`, duration `1/30`, NV12
video-range color attachments, engine adapter/generation, two Metal plane
bindings and surface-lease release all passed. A separate test wrapped decoded
frame 5 as Skia YUVA textures and composited it to a private GPU render target.

The updated workflows pass `macos-media` 10/10 and `macos-visual` 16/16, while
Core and sanitized Core remain 6/6. Every forbidden pixel/fallback/cross-adapter
counter is zero. Machine-readable receipt:
`docs/evidence/G1/artifacts/G1-WP03-hardware-decode-verification.json`.

## Core clock and multi-frame PTS queue slice

Source commit `a697c6a873760366bb957590038cbf3416e644d0` accepts ADR-0009
and makes portable Core `ProjectClock` the physical owner of transport state,
ProjectTime, source generation and epoch. `ViewportRenderSession` is now only a
scheduler/ClockSource adapter; it has no mutable playback position or epoch.

One VideoToolbox session submits all eight compressed access units, waits once,
and publishes eight same-device NV12 surface leases in an immutable exact-PTS
queue. The Skia integration test submits seeks through Core transport for frames
`[3, 7, 1]`; the resulting ProjectTime selects source frames `[3, 7, 1]` and
GPU-composites each without CPU pixel transfer. The workflows pass Core 7/7,
sanitized Core 7/7, media 12/12 and visual 18/18. Machine-readable receipt:
`docs/evidence/G1/artifacts/G1-WP03-clock-sequence-verification.json`.

## Claim boundary

This now proves a bounded all-IDR multi-frame hardware session and central Core
ProjectTime-to-PTS GPU selection on macOS. It does not qualify MP4 demux,
B-frame/VFR/long-GOP production seek, decoded Timeline Video Layer playback,
audio ClockSource/drift, import, export, Windows, iOS, Android, G1 exit or
product codec support.
