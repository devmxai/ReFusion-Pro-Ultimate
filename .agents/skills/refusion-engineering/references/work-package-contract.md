# Work-package contract

Every ReFusion work package needs:

- stable gate/work-package ID;
- user or architectural outcome;
- dependencies and entry evidence;
- minimal read set;
- allowed and forbidden paths;
- contracts and decisions affected;
- platform/profile matrix;
- deliverables and diagnostics;
- acceptance commands and evidence path;
- performance, security, privacy, and licensing impact;
- failure, rollback, stop, and handoff conditions.

Use the repository templates:

- `docs/templates/WORK_PACKAGE.md`
- `docs/templates/CHECKPOINT.md`
- `docs/templates/HANDOFF.md`
- `docs/templates/ADR.md`
- `docs/templates/RFC.md`

A work package is complete only when its observable outcome and evidence are
complete. Compiler success, a schema, adapter shell, test double, or inactive
code path is not completion.
