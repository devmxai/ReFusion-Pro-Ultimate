# Contributing

ReFusion develops through outcome gates and bounded work packages. Start from
`AGENTS.md` and `docs/status/CURRENT.md`; do not select work from research drafts.

Every change must state:

- the active gate and work-package ID;
- user-visible or architectural outcome;
- read set and allowed write scope;
- verification and evidence path;
- failure/rollback behavior;
- platform, performance, security, and licensing impact.

Architecture decisions use ADRs. Large unresolved proposals use RFCs. Accepted
ADRs are append-only records; supersede them with a new ADR rather than editing
history.
